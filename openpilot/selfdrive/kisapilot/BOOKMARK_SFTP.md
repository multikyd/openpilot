# C4 북마크 서버 업로드

C4 수신부와 업로드 대기열을 준비한 상태다. 기사에이전트 앱의 설정 화면과 키 전송 기능은 별도 작업이며, 기존 APK만으로 신규 서버 설정을 입력할 수 없다. 초기값은 업로드 비활성화다. 실제 서버 연결과 C4 기기에서의 실행 확인은 설정 후 진행해야 한다.

## 저장 및 전송

- 북마크가 세그먼트 시작 30초 이전이면 이전·현재 세그먼트, 이후이면 현재 세그먼트만 선택한다. 다음 세그먼트는 기다리지 않는다.
- 기록 중인 `.lock`이 없어지고 파일 크기·수정 시간이 3초 이상 안정된 후 ZIP을 만든다. 원본 영상과 로그는 수정하지 않는다.
- ZIP에는 세그먼트 폴더 아래 qcamera와 qlog/rlog만 담는다. fcamera/ecamera는 보내지 않고 영상 재인코딩도 하지 않는다. 이미 압축된 데이터를 다시 압축하지 않는다.
- 업로드 중에도 새 북마크를 별도 작업으로 등록한다. 미완료 세그먼트와 업로드용 ZIP은 자동 공간 정리에서 보호한다. 서버 장애가 오래 지속되면 저장 공간을 확인해야 한다.
- 대기열과 ZIP은 `realdata/bookmark_uploads`에 보관한다. 전원 차단 후 재시작하면 같은 ZIP을 서버의 `.part` 뒤에 이어 보낸다. 완료 후에만 `.zip`으로 이름을 변경한다. 서버 파일이 삭제되거나 변경되면 정상적인 이어 전송을 보장할 수 없다.
- 기록 도중 전원이 꺼져 오래된 `.lock`이 남는 경우 자동 업로드는 이를 임의로 해제하지 않는다. 이 경우 기록 파일의 정상 종료 여부를 따로 확인해야 한다.

## 집에서 이어서 할 앱 작업

기사에이전트에서 서버 주소·포트·계정·절대 저장 경로·전송 속도를 C4에 저장하고, 휴대폰의 SSH 개인키를 암호화하여 C4로 전송한다. 서버 저장 경로는 `/home/account/realdata` 같은 형식이며 접속 계정에 쓰기 권한이 필요하다. 상위 폴더는 미리 만들어야 한다.

키 선택 → 서버 호스트 키 지문 확인 및 신뢰 → 연결·쓰기 시험 → 자동 업로드 활성화 순서로 연결한다. APK는 집에 있는 기존 앱 서명키로 서명해야 기존 앱에 업데이트할 수 있다.

서버 설정 7개는 C4의 영구 Params에 `DONT_LOG`로 등록된다. 개인키는 `/data/params/kisa_sftp`에 제한된 권한으로 저장되며 일반 파일 탐색기의 다운로드·복사·이동 대상에서 제외된다. 코드와 전송 상태에는 실제 접속 정보를 넣지 않는다. 기존 로컬 기사에이전트 연결을 사용하므로 최초 설정과 키 등록은 신뢰할 수 있는 네트워크에서 한다.

## C4와 앱 연결 규약

- `GET/POST /bookmarks/server/config`: 설정 조회·저장. 숫자 필드는 정수, `enabled`는 불리언이다.
- `GET /bookmarks/server/keys`: C4에 등록된 키 이름만 반환한다.
- `GET /bookmarks/server/key-upload/public`, `POST /bookmarks/server/key-upload`: 일회용 120초 nonce와 RSA-OAEP SHA256/MGF1-SHA256 암호문 조각으로 키를 등록한다. 암호화되지 않은 개인키나 암호가 필요한 키는 받지 않는다.
- `POST /bookmarks/server/host-key`, `POST /bookmarks/server/trust-host`: 지문 표시와 사용자 확인을 분리한다.
- `POST /bookmarks/server/test`, `GET /bookmarks/server/status`: 비동기 연결·쓰기 시험 및 대기열 상태다.
- 기존 `/bookmarks/auto`는 빈 목록을 반환하여 구형 앱과 서버가 중복 다운로드하지 않도록 한다. 수동 내보내기는 유지한다.

C4 화면은 `UPLOAD N WAIT`, `UPLOADING / N WAIT`, `UPLOAD DONE`, `UPLOAD RETRY`를 표시한다. 전송률로 계산한 가짜 진행 퍼센트는 표시하지 않는다. 완료는 서버 최종 파일 크기를 확인한 뒤에만 표시한다.

## 확인 범위

테스트는 세그먼트 선택, 기록 잠금, 대기열 동시 추가, 재시작, 동일 ZIP 재개, 중복 완료 처리, 원본 보호, 공간 정리 제외, 실제 Flask 시작 경로, 실제 OpenSSL 키 복호화 및 로컬 시험 서버에 대한 OpenSSH SFTP 전송을 포함한다. C4 운영체제의 OpenSSH·OpenSSL 실행 파일 및 실제 서버 권한은 기기에서 추가 확인해야 한다. 변경된 Params 등록을 반영하도록 정상 빌드와 재시작이 필요하다.
